 * HIGH-LEVEL FLOW
 * ═══════════════════════════════════════════════════════════════════════════
 *
 * 1) User uploads resume (PDF/Docx) from React frontend
 * 2) Backend validates + stores file temporarily
 * 3) Backend parses file using PDFBox (PDF) or Apache POI (Docx) → raw text
 * 4) Backend sends text to Ollama (llama3.1:8b) with “brutal reviewer” prompt
 * 5) Ollama returns JSON-like feedback (score, verdict, issues, actions)
 * 6) Backend validates minimal fields and stores result in PostgreSQL
 * 7) Frontend shows score, verdict, issues, action items nicely

 *
 * Packages:
 * com.resumeroaster
 *   ├── controller      // REST endpoints
 *   ├── service         // business logic
 *   ├── repository      // JPA repositories
 *   ├── entity          // JPA entities
 *   ├── dto             // request/response objects
 *   ├── exception       // custom exceptions + handler
 *   └── config          // config (WebClient, CORS)
 *
 * Controllers:
 *   - UploadController
 *       POST /api/v1/upload      -> upload resume
 *
 *   - AnalysisController
 *       POST /api/v1/analyze     -> trigger analysis (by uploadId)
 *       GET  /api/v1/analysis/{id} -> fetch analysis result
 *
 *   - HealthController
 *       GET /api/v1/health       -> { status: "ok", timestamp: ... }
 *
 * Services:
 *   - StorageService
 *       validateFile(MultipartFile file)
 *       saveTempFile(MultipartFile file) -> Path
 *
 *   - ResumeParserService
 *       parseResume(MultipartFile file) -> String rawText
 *
 *   - LLMAnalysisService
 *       analyzeWithOllama(String resumeText) -> String analysisJson
 *
 *   - AnalysisService
 *       createAnalysis(uploadId) -> Analysis entity
 *       getAnalysis(Long id)     -> Analysis + mapped DTO
 *
 * Repositories:
 *   - UserRepository extends JpaRepository<User, Long>
 *   - AnalysisRepository extends JpaRepository<Analysis, Long>
 *
 * ═══════════════════════════════════════════════════════════════════════════
 * ENTITIES (JPA)
 * ═══════════════════════════════════════════════════════════════════════════
 *
 * User:
 *   @Entity
 *   @Table(name = "users")
 *   - id: Long           (@Id, @GeneratedValue)
 *   - email: String      (@Column(unique = true, nullable = false))
 *   - name: String
 *   - createdAt: LocalDateTime
 *
 * Analysis:
 *   @Entity
 *   @Table(name = "analyses")
 *   - id: Long           (@Id, @GeneratedValue)
 *   - filename: String   (max 255)
 *   - fileSize: Long
 *   - uploadedAt: LocalDateTime
 *   - parsedText: String (@Column(columnDefinition = "TEXT"))
 *   - analysisJson: String (@Column(columnDefinition = "TEXT"))
 *   - overallScore: Integer
 *   - tierPlacement: String  (e.g., "SERVICE_COMPANY")
 *   - createdAt: LocalDateTime

 * LLM OUTPUT FORMAT (MVP – SIMPLE)

 *
 * Expect Ollama to return JSON like:
 *
 * {
 *   "overallScore": 6,
 *   "tierPlacement": "SERVICE_COMPANY",

 *   - check "overallScore" exists and is 1–10
 *   - other fields optional in MVP

 * ═══════════════════════════════════════════════════════════════════════════
 * OLLAMA INTEGRATION
 * ═══════════════════════════════════════════════════════════════════════════
 *
 * Prerequisites:
 *   - Install and run Ollama locally
 *   - Download model once: ollama pull llama3.1:8b
 *
 * Base URL:
 *   - Default: http://localhost:11434
 *
 * Request (POST /api/generate):
 *
 * {
 *   "model": "llama3.1:8b",
 *   "prompt": "System: You are a brutal resume reviewer for software engineering candidates. Be honest and specific.\n\nUser: {resumeText}",
 *   "stream": false,
 *   "format": "json",
 *   "options": {
 *     "temperature": 0.3,
 *     "num_predict": 2048
 *   }
 * }
 *
 * Response:
 * {
 *   "model": "llama3.1:8b",
 *   "response": "{...JSON from schema above...}",
 *   "done": true
 * }
 *
 * Implement LLMAnalysisService using Spring WebClient:
 *
 * - Build request body (model, prompt, stream=false, format="json")
 * - POST to /api/generate
 * - Read response.response (String)
 * - Return that JSON string
 * - Handle timeout + errors → throw custom LLMException
 *
 * ═══════════════════════════════════════════════════════════════════════════
 * VALIDATION & ERROR HANDLING
 * ═══════════════════════════════════════════════════════════════════════════
 *
 * File validation rules:
 *   - Max size: 5MB (5 * 1024 * 1024)
 *   - Allowed types:
 *       "application/pdf"
 *       "application/vnd.openxmlformats-officedocument.wordprocessingml.document"
 *
 * Custom exceptions:
 *   - FileTooLargeException
 *   - InvalidFileTypeException
 *   - ParsingException
 *   - LLMException
 *
 * GlobalExceptionHandler:
 *   - Map specific exceptions to HTTP status + ErrorResponse
 *   - FileTooLargeException     → 413 ERR_FILE_TOO_LARGE
 *   - InvalidFileTypeException  → 400 ERR_INVALID_FILE_TYPE
 *   - ParsingException          → 400 ERR_PARSING_FAILED
 *   - LLMException              → 500 ERR_LLM_FAILED
